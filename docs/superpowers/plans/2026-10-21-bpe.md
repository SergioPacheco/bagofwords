# Tokenização BPE — plano de implementação

**Objetivo:** integrar BPE real e didático no HTML existente, preservando todas as funcionalidades. Requisitos: especificação fornecida pelo usuário nesta conversa.

**Arquitetura:** núcleo `BPE` em um script próprio, sem DOM; interface em script separado após a inicialização do laboratório. Base UTF-8 com IDs 0–255, merges sequenciais a partir de 256, pares contados dentro de segmentos de texto sem espaços ou em cada caractere de espaço. Sem normalização. Desempate por IDs numéricos dos pares. Corpus limitado a 16.000 bytes, entrada a 16.000 bytes, máximo de 100 merges, para execução síncrona previsível. Informar limites na interface.

**Preservação:** aba adicionada ao tablist existente; os dados de BPE são independentes de BoW. Sem bibliotecas, APIs, modelos ou mudanças no núcleo NLP. A versão de origem contém PCA, mas não contém t-SNE.

## Pontos de revisão

- Bytes incompletos de acentos/emojis devem aparecer em hexadecimal, sem fingir que cada byte é uma letra.
- Preservar BOM, quebras de linha, espaços, caracteres combinantes e ordem; rejeitar UTF-16 malformado com mensagem explícita.
- Corpus alterado não pode deixar resultados antigos aparentando corresponder aos novos dados; erro não deve esconder BoW.
- Merges podem terminar antes do solicitado se não houver pares; pares sobrepostos são contados, mas unidos sem sobreposição.
- Sequência numérica BPE não é um embedding; IDs pertencem exclusivamente ao modelo treinado localmente. Resultados PT/EN dependem do corpus e não reproduzem GPT/Qwen.
